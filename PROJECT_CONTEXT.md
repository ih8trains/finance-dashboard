## Главные договорённости
- Пользователь предпочитает короткие ответы и выполнение работы без длинных объяснений.
- Интеграция с Т‑Банком работает только на чтение операций. Переводы денег/платёжные действия не реализуются и не нужны.
- Не просить пользователя повторно экспортировать XLSX или вручную переносить данные, если данные уже доступны через подключённые интеграции.
- Архивы уже созданы. Не запускать повторную миграцию/пересборку без отдельной причины.
- Google Sheets не удалять и не менять, пока дашборд полностью не работает на GitHub и пользователь отдельно не подтвердил удаление.
- Не добавлять посредников (Cloudflare Worker, Firebase, собственный сервер и т. п.). Пользователь хочет простое хранилище на GitHub, защищённое паролем.

- `loadDashboard(pass)` загружает `data/manifest.json` и месячные архивы со статусом `verified` напрямую с GitHub Raw; GAS для загрузки операций не вызывается.

## Реализация зашифрованного user-data файла — первый проход сделан
- Коммит `89f1a93` изменил `index.html`.
- Добавлена загрузка `data/user-data.json.enc` с GitHub Raw при входе. Если файла ещё нет (HTTP 404), используются пустые пользовательские данные/настройки по умолчанию.
- Файл расшифровывается в браузере тем же паролем входа: AES-GCM, PBKDF2-SHA-256, 600 000 итераций, отдельные случайные salt и IV.
- В зашифрованном payload сохраняются labels (группы, роли, контекст, человек, проект, возмещения, теги, комментарии), settings (бюджет, лимиты, цели, регулярные платежи, скрытые рекомендации) и rules.
- `saveLabel`, `saveMeta`, `flushPendingLabels` больше не отправляют пользовательские данные в GAS; они вызывают `saveUserData()`.
- Прямая запись выполняется браузером в GitHub Contents API. При первом сохранении создаётся файл, при следующих — обновляется с SHA текущей версии.
- Для записи нужен Fine-grained GitHub PAT с Contents: Read and write только для `ih8trains/finance-dashboard`. Токен запрашивается при первом сохранении и хранится только в переменной памяти вкладки; в localStorage, HTML и зашифрованный файл не записывается. Это GitHub-авторизация, не платёжный доступ и не посредник. Банковская интеграция остаётся только для чтения.
- Локальный pending cache остаётся как резерв до успешной записи; после успешной записи очищается.
- JS syntax проверен через `new Function(script)` — OK. Полный браузерный тест загрузки/записи ещё не проведён; нужно проверить GitHub PAT и CORS из GitHub Pages.
- Старые GAS-функции архивирования и `api()` оставлены, но пользовательское сохранение через них отключено. Не удалять GAS и Google Sheets до полного теста.


## Решение по хранилищу — зафиксировано
- Хранилище пользовательских данных — отдельный зашифрованный файл в этом же GitHub-репозитории, например `data/user-data.json.enc`.
- Внутри файла JSON со структурой версии и данными: ручные группы/labels по ID операции, комментарии, правила, настройки интерфейса и бюджетные данные, если пользователь подтвердит их перенос.
- Шифрование выполняется в браузере паролем пользователя: AES-GCM; ключ выводится PBKDF2-SHA-256 через Web Crypto. На GitHub отправляется только ciphertext и открытые технические метаданные, необходимые для расшифровки (salt, iv, версия формата/KDF). Пароль и ключ на GitHub не сохраняются.
- При загрузке: получить файл с GitHub → запросить/использовать введённый пароль → расшифровать → проверить формат → применить разметку и настройки к дашборду.
- Не использовать Cloudflare Worker, Firebase, Apps Script или другой сервер-посредник.
- Для записи в GitHub браузеру всё равно нужна авторизация GitHub с правом записи в репозиторий. Банковский API остаётся read-only; это отдельный вопрос. Простой прямой вариант без посредника — пользовательский GitHub Personal Access Token с минимальным доступом только к Contents этого репозитория. Токен нельзя вшивать в публичный HTML, коммитить или сохранять в открытом виде. Предпочтительно вводить его отдельно и держать только в памяти текущей сессии; если пользователь не хочет вводить токен, автоматическая запись из браузера в GitHub без посредника невозможна.
- Чтение файла остаётся публичным через GitHub Raw. Перед записью нужно учитывать SHA текущего файла, чтобы не перезаписать более свежую версию.
- Локальный кэш можно оставить как ускорение/аварийный буфер, но GitHub-файл должен быть основным синхронизируемым источником.
